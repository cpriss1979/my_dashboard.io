GOOGLE SIGN-IN AND CLOUD SYNC — GITHUB PAGES

Upload these THREE files to the SAME top-level folder in your GitHub repository:
  index.html
  firebase-sync.js
  sync-core.js

Keep Firestore's private user rules published (the included firestore.rules matches the rules you already published). Enable Google authentication and authorize cpriss1979.github.io. No secret keys or admin credentials belong in this code. This package uses your public Firebase web configuration.

FIRST USE
1. Export a backup from your existing dashboard before replacing it.
2. Open https://cpriss1979.github.io/my_dashboard.io/ in Chrome or Safari after GitHub Pages deploys.
3. Sign in with Google.
4. If you want your existing browser entries in that account, choose Import this device. This is an explicit replacement of that account's current cloud copy, not an automatic merge. Do it once from the device/browser holding the data you want. The original local-only copy remains intact.
5. Wait for Saved to your Google account / Cloud connected.
6. On your other device, open the same address and sign in with the SAME Google account. Do not import an empty device over existing cloud data.

Each Google account uses a separate browser cache and Firestore path: users/GOOGLE_UID/dashboard/state. Browser caches are not copied between accounts. Signed-out users must choose local-only mode before viewing this browser's original local data. Anyone with access to the same computer/browser profile can access that profile's local storage; use separate OS/browser profiles on shared computers.

SYNC AND OFFLINE
Changes are saved locally immediately and sent after a short pause. Game records, Journal drafts and main dashboard data sync together. During offline use, changes stay queued on that account's browser cache. Simultaneous edits on two devices can produce a conflict; export your local backup, then Load latest. Import this device means the ORIGINAL local-only data, not the signed-in cache. Restore backup can import another exported dashboard into your signed-in account.

PLASH
Google may reject authentication in embedded browsers such as Plash. Signing in through Chrome does NOT sign Plash in, because they have separate browser storage. This package retains local-only mode for Plash and does not bypass Google's embedded-browser restrictions. Test Google login in a normal browser first. A Plash-compatible sign-in would require an additional supported authentication flow.

The Firebase sign-in and two-device sync need to be tested with your Google account after deployment. Code checks do not substitute for that end-to-end test. Your existing chatgpt.site copy is not changed by this package.
